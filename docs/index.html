Nothing in the middle

Most connectors ask you to hand your Garmin credentials to somebody else’s server. This one runs on hardware you control. The installer sets everything up under your own user, registers the connector as a service that starts with the machine (systemd or launchd) and prints the sign-in links.

Install

Linux and macOS. The script installs Tailscale when it needs it (--tailscale, --tailscale-serve, --funnel) and --no-sudo forbids any privilege escalation, implicit when running as root.

--funnel exposes the MCP endpoint and OAuth surface to the public Internet: the access token is the only thing gating it. --tailscale-serve is private, but it does not work for claude.ai’s or Claude Desktop’s “Add custom connector”: that feature is called from Anthropic’s own servers, never your tailnet. Use it only for clients that run directly on one of your tailnet machines (Claude Code, etc).

Connect a client

Local clients call the connector directly and can use a private URL. claude.ai’s “Add custom connector” is called from Anthropic’s own servers instead, so it always needs a public HTTPS address.

  1. Get a public HTTPS address

    Only needed for the “Add custom connector” row above. --funnel at install time gives a permanent https://<machine>.<tailnet>.ts.net that survives reboots (see the warning below). The Create HTTPS link button on the setup page gives a Cloudflare quick tunnel instead, also public, and its URL changes at every restart. Claude Code / Desktop’s local config can instead use a private --tailscale-serve address or the plain token URL: no public exposure needed there.

  2. Add the connector

    Paste the HTTPS base URL followed by /garmin/, with no token.

  3. Authorize

    claude.ai opens the connector’s authorization page: paste the access token from garmin-mcp url or the setup page, and approve. The authorization persists.

Funnel and quick tunnels are public

Anyone who obtains the access token can call the MCP endpoint through them: the token is the only gate (sign-in, health and disconnect stay private, unknown paths 404). --tailscale-serve is private but cannot be used for claude.ai’s/Desktop’s “Add custom connector” at all: that flow is always called from Anthropic’s servers, never your tailnet.

If it fails: DNS still propagating

If claude.ai cannot reach the server right after enabling Funnel, wait a few minutes. If it persists, rename the machine in the Tailscale admin console (a fresh DNS name resolves immediately) and re-run the installer.

How it works

One process on your machine, two ways in, and only one of them is reachable from the internet.

  • browser

    Signs in on the setup page: the password goes straight to Garmin SSO and is never stored

  • garmin-mcp

    The connector, on your machine. OAuth tokens in ~/.config/garmin-mcp/. Talks to Garmin SSO + the Connect API

  • /garmin/

    MCP endpoint: the per-install token as ?token=, as a path prefix /t/<token>/garmin/, or as a Bearer header. Local clients, direct: Claude Code, Desktop’s local config, or --tailscale-serve for any client on your tailnet

  • public HTTPS entry

    Funnel or quick tunnel: only the MCP endpoint and the OAuth surface answer; sign-in, health and disconnect stay private, everything else returns 404. claude.ai / “Add custom connector”, called from Anthropic’s servers (OAuth 2.1 + PKCE)

With Funnel or a quick tunnel, internet scanners probing the public address are normal: everything they touch returns 404. --tailscale-serve skips this entirely for direct local clients, but it’s a separate, private address that claude.ai’s “Add custom connector” can never reach: that flow always needs the public one.
